# Ангасолка: сайт и backend

Рабочая копия фронтенда из задачи «Создать фронт сайта турбазы» перенесена в `public/`. Исходная копия в другой задаче не менялась. Разработка далее ведётся в этой папке.

## Запуск

Для полного бесплатного теста по публичной ссылке: `Запустить демо.cmd`. Фронтенд, backend, админка и CRM работают с отдельной тестовой БД; Telegram подключается через `Настроить Telegram.cmd`. Доступ и остановка — [docs/demo.md](docs/demo.md).

Требуется Node.js 24 LTS и pnpm 11. В этом компьютере `Start.ps1` также находит Node из установленного Codex.

```powershell
pnpm install --frozen-lockfile
pnpm start
```

Или запустите `Открыть сайт.cmd` для локального просмотра без отправки Telegram-уведомлений. Адрес: http://127.0.0.1:4180. Сервер нужно оставить работающим; файл `public/index.html` напрямую открывать нельзя. Данные сохраняются в `data/postgres/`. Второй сервер с этой же локальной БД запускать нельзя.

```powershell
pnpm check
pnpm test
```

Настройки из `.env` загружаются автоматически; пример — `.env.example`. Для отдельного PostgreSQL задайте `DATABASE_URL`, выполните `pnpm db:migrate`, затем `pnpm start`. В production автоматические миграции отключены, обязательны PostgreSQL и HTTPS `PUBLIC_ORIGIN`. PGlite используется только для локальной разработки и тестов. Переключение URL не переносит локальные данные автоматически.

## Что работает

- Каталог из БД; предварительный расчёт на странице и обязательный серверный расчёт перед отправкой.
- Койко-места × ночи; отдельные количества порций, часов бани и участников занятий. Скидка применяется только к проживанию. Денежные величины API — целые копейки.
- Приём заявок с контактами, согласием и проверкой цены. Одна транзакция сохраняет клиента, заявку, позиции, событие и outbox.
- Повторная отправка с тем же `Idempotency-Key` и телом возвращает ту же заявку. Изменённое тело с тем же ключом отклоняется. В браузере ключ сохраняется в памяти до перезагрузки.
- Секретный код статуса генерируется браузером из 32 случайных байт. БД хранит SHA-256; код не попадает в URL, access-log или localStorage. Код доступен в подтверждении, его нужно скачать. Потерянный код автоматически не восстанавливается.
- `/status.html` показывает номер, статус и сумму без контактов. Публичного списка заявок нет.
- `/admin/` — кабинет сотрудников: обзор метрик, заявки, блоки сайта, каталог услуг, медиатека, аудит и контролируемый просмотр БД.
- Встроенная CRM в `/admin/`: воронка заявок, ответственные, задачи со сроками по Иркутску, внутренние заметки и фильтры внимания. Сравнение решений и инструкция — [docs/crm.md](docs/crm.md).
- Версионированные SQL-миграции, OpenAPI, проверки здоровья, лимиты запросов, ограничение размера тела, CSP и проверка Origin.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/catalog` | Каталог и политика скидок |
| POST | `/api/v1/quotes` | Серверный расчёт |
| POST | `/api/v1/orders` | Сохранить заявку; заголовок `Idempotency-Key` |
| GET | `/api/v1/orders/status` | Статус; `Authorization: Bearer <код>` |
| GET | `/api/v1/health` | Процесс работает |
| GET | `/api/v1/ready` | БД доступна |
| GET | `/api/v1/openapi.json` | Контракт API |

Пример тела расчёта (замените даты на будущие):

```json
{"arrival":"2027-06-10","departure":"2027-06-15","beds":2,"extras":{"food":4,"bath":2}}
```

Для создания добавьте `customer: {name, phone}`, `comment`, `consent: true`, `expectedTotalMinor`, `pricingVersion` из расчёта и `trackingToken` (64 hex-символа, криптографическая случайность). `source` клиент не передаёт. Изменившаяся цена возвращает `409 PRICE_CHANGED` и требует повторного просмотра суммы. Валюта — RUB, календарь турбазы — Asia/Irkutsk.

## Границы текущего этапа

Тарифы 1500 / 2500 / 3500 / 1800 / 2000 / 650 ₽ и скидка 10% от 5 ночей перенесены из демо-фронта, не утверждены владельцем. Заявка `pending` не является подтверждённой бронью, не уменьшает остаток мест и не принимает оплату. Реальный инвентарь, расписание и правила отмены не выдуманы.

В админке есть авторизация сотрудников с ролями owner/manager/viewer, сессии в HttpOnly cookie, блокировка после неудачных входов, optimistic locking и аудит. Встроенная CRM работает с теми же заявками. Внешняя CRM пока не подключена. Реализован выключенный по умолчанию Telegram-адаптер: заявки через диалог, отслеживание по коду сайта, уведомления сотруднику и принятие в работу. Worker читает общую outbox с повторной доставкой. В тестовом запуске 21 сентября 2026 подключён настоящий бот через HTTPS webhook; владелец подтвердил ответ на `/start` и получение уведомления о заявке сайта. Настройка — [docs/telegram.md](docs/telegram.md), результаты демо — [docs/demo.md](docs/demo.md). GPT API не вызывается, ключ OpenAI сейчас не нужен.

Для публикации отдельно потребуются: утверждённые тарифы и текст обработки данных с реквизитами оператора, настройка сервера/PostgreSQL/HTTPS, резервного копирования и восстановления, доставка заявок сотруднику. Rate limiting сейчас в памяти одного процесса; при нескольких инстансах нужен общий limiter. По умолчанию `TRUST_PROXY=none`; для единственного Nginx на том же сервере поддержан `TRUST_PROXY=loopback` с привязкой приложения к loopback.

### HTTPS и сертификаты Минцифры

Добавлены прямой TLS через `TLS_CERT_FILE`/`TLS_KEY_FILE`, проверка `pnpm tls:check` и шаблон Nginx. В production теперь нужно явно настроить прямой TLS или `TRUST_PROXY=loopback` за HTTPS-прокси. Формат сертификатов — PEM, включая цепочку промежуточных УЦ; проверка домена и ключа выполняется до запуска. Сам сертификат для домена не выпущен и не установлен. Доверие браузера посетителя требует отдельной проверки. [Инструкция и границы совместимости](docs/tls-russia.md).

### Первый вход в админку

В development при пустой БД откройте `http://127.0.0.1:4180/admin/` и создайте владельца с паролем от 12 символов. Для production первичного владельца создайте интерактивно на сервере (пароль не попадает в историю shell):

```powershell
pnpm admin:create
```

В production задайте `ADMIN_SESSION_KEY` как 64 строчных hex-символа и выполните `pnpm db:migrate` до запуска приложения. Владелец может создавать и отключать сотрудников, менеджер редактирует контент, каталог и заявки, viewer имеет только чтение.

Архитектура и дальнейшие шаги — `docs/architecture.md`; правила разработки с Astra — `AGENTS.md` и `docs/astra-workflow.md`.

### Тест-кейсы и чек-листы

Постоянный [бэклог дефектов](docs/backlog/README.md) хранит сообщения об ошибках, их области, приоритеты, критичность и историю исправлений. Запросы вроде «исправь фронт» выполняются по открытым карточкам этой области. Закрытые дефекты сохраняются вместе с результатами проверок.

Постоянный [каталог тестирования](docs/testing/README.md) содержит отдельные папки фронтенда, бэкенда и админки/CRM, подготовку данных и шаблон отчёта. При запросе «протестируй» начинать с него; результаты запусков хранить в `docs/testing/runs/`. Наличие кейса не означает, что проверка уже выполнена.
