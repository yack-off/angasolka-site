# Работа над backend с GPT-6 Astra

На этом этапе Astra используется как помощник разработки; runtime-зависимости от GPT нет. Модель не настраивается package.json: она выбирается в задаче Codex. Текущая задача уже работает на GPT-6 Astra; настройки интерфейса пользователя не изменялись.

Для сложных транзакций, миграций и прав доступа выбирать high, для обычных ограниченных правок medium/low; оценивать по результатам проверок, а не максимальному reasoning для каждой задачи. Это рабочая рекомендация проекта, не обещание оптимальной цены. Официальная документация рекомендует явно задавать границы задачи, инициативность и объём тестирования, а также проверять инструкции AGENTS.md.

Задавать задачу через конкретный сценарий, инварианты и критерии приёмки. Пример:

> Добавь отмену заявки владельцем через подтверждённую идентичность. Сохрани старую цену, проверь допустимость перехода и версию заказа. Обнови аудит/outbox в той же транзакции. Добавь проверки чужой заявки, повторной отмены и конкурентного изменения; выполни check/test, обнови OpenAPI и README. Не добавляй оплату или интерфейс CRM.

Рабочий цикл: прочитать затрагиваемые модули → изменить один вертикальный сценарий → проверить негативные и конкурентные случаи → обновить контракт и документы → назвать фактически проверенное и оставшиеся ограничения. Не менять одновременно стек, UI и бизнес-правила без потребности задачи. Не запускать бесконечно одинаковые тесты после успешной проверки неизменённого кода. Модели передавать синтетические контакты, не реальные выгрузки клиентов и не секреты.

Когда появится бот: модель передавать через серверную настройку; для GPT-6 Astra использовать Responses API с function tools, валидировать аргументы, разрешать только ограниченные операции. Нужны тайм-ауты, лимит расходов/числа tool calls, журнал без персональных данных, набор eval-сценариев на русские даты и неоднозначные количества. API-ключ только на сервере. Не использовать свободный SQL, универсальный admin tool или доверие к инструкциям внутри пользовательских сообщений. Вызов создания заказа идемпотентный и только после подтверждения состава гостем.

Официальный источник: [GPT-6 Astra model guidance](https://developers.openai.com/api/docs/guides/latest-model). Перед будущей API-интеграцией заново проверить актуальный контракт SDK/API и доступ модели у владельца.
