# Бэкенд: тест-кейсы

Предусловия и данные — [подготовка](../test-data.md). API имеет префикс `/api/v1`. Для каждого отказа записи дополнительно проверить отсутствие частичных изменений. Проверки хешей, транзакций и инъекций отказа выполняются через тестовый harness на отдельной БД. Все кейсы изначально NOT RUN.

| ID | Приоритет | Сценарий и действия | Ожидаемый результат |
|---|---|---|---|
| BE-01 | P0 | GET catalog, health, ready, openapi.json; сверить каталог с тестовой БД. | 200; каталог содержит активные услуги, текущую политику, RUB и Asia/Irkutsk; health/ready соответствуют состоянию; контракт доступен. |
| BE-02 | P0 | POST quotes для Q, услуги без мест, на пороге скидки и ниже; сравнить независимую формулу. | Целые копейки; скидка только на bed-nights; услуги считаются по количеству, `availability=requires_confirmation`; расчёт не создаёт заказ. |
| BE-03 | P1 | Отправить несуществующую дату, неправильный формат; заезд D−1/D/D+730/D+731; 0/1/365/366 ночей; високосный день; отдельно время по обе стороны полуночи Иркутска. | Реальные даты и допустимые границы принимаются, остальные — 400 `INVALID_DATE`/`INVALID_PERIOD`; календарь не зависит от UTC-дня или часового пояса клиента. |
| BE-04 | P1 | В quotes/orders перебрать места −1/0/1/20/21, услуги −1/0/1/100/101, дроби/строки/null; неизвестные и отключённые услуги с ненулевым количеством; пустую поездку. | Невалидные типы/границы отклоняются 400; неизвестная/отключённая услуга — `SERVICE_UNAVAILABLE`; без позиций — `EMPTY_ORDER`. 0 мест допустим при наличии услуги. |
| BE-05 | P0 | Добавить в публичную заявку цену позиции, source, status, role, assigneeId; неизвестные вложенные поля; убрать обязательное поле. | 400; сервер не принимает клиентское назначение цены/источника/статуса/прав/CRM-полей. |
| BE-06 | P1 | Проверить contacts/consent: пробельное имя, длины 80/81, телефон 9/10/15/16 цифр и буквы, comment 1000/1001, consent false/отсутствует; JSON с неверным Content-Type и повреждённый JSON. | Валидные синтетические контакты принимаются и нормализуются; плохие поля дают 400, неподдерживаемый тип тела — 415; частичных записей нет. |
| BE-07 | P0 | Создать O с новым ключом; проверить заказ, клиента, позиции, событие и outbox в БД. | 201; одна согласованная транзакция, pending, источник website, снимок расчёта совпадает с quote; код хранится только как SHA-256. |
| BE-08 | P0 | Повторить тот же ключ и тело последовательно и параллельно; сравнить ID и количество записей. | Одна заявка, один набор позиций/событий/outbox; повтор возвращает 200 с той же заявкой, исходное создание — 201. |
| BE-09 | P0 | Повторить ключ с изменённым телом; отдельно убрать ключ, задать длину 19/20/100/101 и недопустимые символы. | Изменённое тело — 409 `IDEMPOTENCY_CONFLICT`; невалидный/отсутствующий ключ — 400, допустимые границы работают с новым валидным телом. |
| BE-10 | P0 | Подменить expectedTotalMinor; отдельно изменить цену/политику после quote и отправить старую pricingVersion. | 409 `PRICE_CHANGED`, нет клиента/заявки/занятого ключа от неудачной операции; требуется новый расчёт. |
| BE-11 | P0 | Создать заказ, затем изменить тарифы владельцем; прочитать старую заявку и рассчитать новую. | Старые позиции, сумма и снимок неизменны; новый quote использует новую версию. При гонке правки тарифа и заказа нет смешанного снимка. |
| BE-12 | P0 | Инъецировать отказ вставки outbox/события в создание заказа; повторить без отказа. | Полный rollback клиента/заказа/позиций/идемпотентности/событий; последующий повтор может успешно создать ровно одну заявку. |
| BE-13 | P0 | GET orders/status без Bearer, с неверным форматом и неизвестным корректным кодом; затем с кодом O. Попробовать получить статус только по телефону/ID. | 401 для отсутствующего/невалидного секрета, 404 для неизвестного; корректный код даёт минимальный ответ без контактов, комментария, CRM и токена. Телефон/ID не дают доступ. |
| BE-14 | P1 | Две разные заявки с одинаковым синтетическим телефоном, разными ключами и кодами. | Отдельные клиенты и заявки; нет автоматического объединения/доступа по непроверенному телефону. |
| BE-15 | P0 | Запросить `.env`, исходники, миграции, пути с traversal; проверить CSP/no-store; выполнить мутацию с чужим Origin и `Sec-Fetch-Site: cross-site`; проверить очищенные логи. | Служебные файлы недоступны; cross-site запись — 403; API no-store, CSP ограничивает источники; в логах нет контактов, кодов, cookie, Authorization или тела с секретами. |
| BE-16 | P1 | На отдельном стенде превысить лимиты orders/status/общий; отправить тело >16 КиБ в публичный API, затем корректный запрос после окна лимита. | 429 `RATE_LIMITED`, oversized — 413; после окна сервис работает; лимитер одного процесса не выдаётся за общий для нескольких инстансов. |
| BE-17 | P1 | На новой БД применить миграции runner, повторить; сохранить O, корректно закрыть и открыть БД; отдельно сделать БД недоступной. | Миграции 001–004 применяются однократно (актуальный список сверить с runner); данные сохраняются; при отказе БД ready не возвращает ложный 200, health проверяет процесс; ошибки без SQL/секретов. |
| BE-18 | P0 | Выполнить AD-04/AD-05/AD-10 и AD-24–AD-28 через API; отозвать права между чтением и записью; инъецировать отказ outbox в CRM. | Права повторно проверяются в операции, версии и дедупликация защищают запись, CRM/события/аудит/outbox откатываются вместе; приватный текст не утекает. |
| BE-19 | P1 | С подставным Telegram transport проверить secret webhook, дубли update, постороннего staff ID, старую кнопку подтверждения и изменение цены; пройти диалог до подтверждения. | Запись только после подтверждения актуального расчёта; один заказ source=bot; чужой staff не меняет статус; используется общая операция заявки. Реальные сообщения не отправляются. |
| BE-20 | P1 | С подставной доставкой повторить outbox event, сбой сети, retry/lease, отзыв staff и stop подписки; проверить выключенную конфигурацию. | Задания дедуплицируются по событию, повторы контролируются; после отзыва/stop нет запрещённых новых отправок; секретные ошибки не сохраняются. Выключенный адаптер не отправляет; exactly-once не обещается. |
| BE-21 | P1 | Использовать тестовые TLS-сертификаты: верный, истёкший, неверный SAN/ключ, недоверенный CA; проверить cookie и Origin через HTTPS. | Неверная конфигурация отклонена; доверенный сертификат даёт корректный TLS; Secure cookie для HTTPS. Доверие реального браузера к конкретному УЦ проверяется отдельно. |
| BE-22 | P1 | Прогнать тесты demo-proxy/transport: поддельные forwarding-заголовки, неверный host/HTTP; проверить публичный bootstrap и явный trustProxy. | Недоверенные заголовки не дают локальные права, публичное создание владельца запрещено; production требует корректную HTTPS-конфигурацию. Туннель для этого кейса не публикуется. |
| BE-23 | P1 | В тестовом каталоге задать дробную скидку в копейках через подходящие целые цены, затем большую сумму около 2147483647 и выше. | Округление скидки до целой копейки; нулевой итог/превышенный subtotal отклоняются `TOTAL_OUT_OF_RANGE`; нет overflow или отрицательной суммы. |
| BE-24 | P1 | Проверить OpenAPI против фактических публичных/admin/CRM маршрутов; отправить SQL-подобные строки в разрешённые текстовые поля и неверные UUID/page. | Контракт отражает схемы и security; текст остаётся данными, запросы параметризованы; неверные параметры — 400, отсутствующая сущность по валидному ID — 404 там, где предусмотрено контрактом. |

Конкурентные BE-08/BE-11/BE-18 дополнительно выполнять на отдельном PostgreSQL при изменении блокировок/транзакций. Если доступен только PGlite, явно отметить PostgreSQL-ветку BLOCKED. Будущий конкурентный инвентарь описан в [границах](../README.md).
