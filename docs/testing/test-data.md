# Среда и тестовые данные

## Изоляция

- Запускать только на выделенной тестовой БД; перед любыми записями установить, какую БД использует процесс. Не удалять и не сбрасывать `data/postgres` и `data/demo/postgres` ради тестов. Два сервера с одной локальной PGlite-базой одновременно не запускать.
- Обычный `pnpm start` использует постоянные данные и не считается изолированным стендом. Для браузерного прогона доступны `scripts/admin-browser-server.ts` и `scripts/crm-browser-server.ts`; сначала прочитать выбранный скрипт, проверить параметры и адрес. CRM-стенд: переменная `CRM_BROWSER_PASSWORD`, команда `pnpm exec tsx scripts/crm-browser-server.ts`, адрес `http://127.0.0.1:4182`, логин `crm-browser`, БД в памяти. Секрет задавать в окружении без записи в историю команд или отчёт.
- Для первичной настройки и общего браузерного пути: `pnpm exec tsx scripts/admin-browser-server.ts`, адрес `http://127.0.0.1:4181`, пустая БД в памяти и разрешённый локальный setup. Публичный сайт и админка работают на одном порту выбранного стенда; его данные исчезнут после остановки.
- Для тестов с `TEST_DATABASE_URL` использовать только отдельную расходуемую PostgreSQL-базу. Перед запуском прочитать hooks очистки выбранного набора. Не направлять тесты на рабочую БД. Не включать Telegram worker с настоящими учётными данными.
- Данные создавать через существующие операции/API; для отказов транзакции, замены времени и счётчиков допустим контролируемый тестовый harness на отдельной БД. Если такого инструмента нет, результат BLOCKED, а не предположение.
- Заканчивая прогон, остановить только запущенный для него процесс. Удалять лишь созданные этим прогоном временные данные, не чужие файлы и записи.

## Независимый расчёт

Ночи = календарная разница выезда и заезда, интервал `[arrival, departure)`. Проживание = цена `bed` × места × ночи. Допуслуги = сумма «цена × количество за поездку», без умножения на ночи. Если достигнут `discount_nights`, скидка = округлённое до целой копейки произведение стоимости проживания на `discount_percent / 100`. Итог = проживание + услуги − скидка. Считать независимо от функции приложения по каталогу C.

Границы API: места 0/1/20/21; услуги 0/1/100/101; также −1, дробь, строка, null; ночи 0/1/365/366; заезд D−1/D/D+730/D+731. UI выбора гостей сейчас предлагает 1–8, отсутствие проживания выбирается отдельной опцией; границы 20/21 проверяются через API.

## Браузеры и артефакты

Базовый проход: доступный Chromium, ширина 1440 и 390 px; расширенный: 320/768/1024 px, Firefox/WebKit при наличии, масштаб 200%, клавиатура. Записывать фактические браузер, версию и размеры. Недоступный браузер не считать проверенным.

Скриншоты, сетевые трассы и скачанный файл заявки могут содержать код, cookie и контакты. В отчёт прикладывать обезличенные артефакты; не сохранять полные Authorization/Cookie, тела с контактами, секретные коды или строку подключения. Скачивание самого кода — часть функции сайта; проверять локально и не прикладывать исходный файл к общему отчёту.
