# Общая тестовая версия через туннель

`Запустить демо.cmd` запускает тот же фронтенд, Fastify, кабинет, CRM и Telegram-адаптер. Cloudflare Quick Tunnel выдаёт временный HTTPS-адрес. Покупать домен или сервер не нужно. Компьютер должен оставаться включённым без сна и с интернетом; после перезапуска ссылка меняется.

## Данные и доступ

Публичное демо использует отдельную постоянную тестовую БД `data/demo/postgres`, миграции 001–004 и исходный каталог/контент. Рабочая БД `data/postgres`, её заявки, контакты и аккаунты не публикуются и не изменяются. Это настоящие прикладные операции на тестовых данных, а не макет. Тестовые заявки сохраняются после остановки демо. Тарифы остаются демонстрационными; подтверждения наличия мест и оплаты нет.

При первом запуске создаётся отдельный владелец со случайным паролем. Логин и пароль находятся только в `data/demo/admin-access.txt`; файл вне `public/`, исключён из Git. Не передавайте его посетителям сайта. Для тестировщиков кабинета владелец может создать отдельные аккаунты с подходящими ролями.

Папка `data/demo` содержит секреты и тестовые записи. Не прикладывайте её к публичным архивам. Бэкап этой PGlite-базы делайте только после остановки демо.

## Telegram

1. Создайте отдельного тестового бота через BotFather.
2. Откройте `Настроить Telegram.cmd`. Введите токен в скрытое поле терминала. Не отправляйте токен в чат.
3. Отправьте показанную команду `/connect ...` своему боту из личного Telegram. Код одноразовый и истекает через пять минут. Первый посторонний `/start` не может присвоить доступ сотрудника.
4. Настройка сохраняет токен, webhook-секрет и подтверждённый Telegram ID в `.env`. Если бот уже обслуживается другим webhook, переключение отдельно подтверждается в терминале. До этого webhook не меняется.
5. Запустите демо. При включённом Telegram оно проверит публичный HTTPS, зарегистрирует webhook с секретом, запустит очередь уведомлений. Сотрудником по умолчанию становится владелец тестового кабинета. Не задавайте `TELEGRAM_STAFF_ID` из рабочей БД для демо.
6. Отправьте `/start`, затем `/new` и пройдите диалог. Проверьте заявку в CRM и «Принять в работу». Заявку с сайта подключайте через `/link КОД` в личном чате с ботом.

Настоящие уведомления отправляются только после явного `TELEGRAM_ENABLED=true`. При запуске обрабатываются накопленные события **тестовой** базы. Пока Telegram не настроен, остальная система работает. Для подключения после настройки остановите и снова запустите демо; новая ссылка запишется в `data/demo/links.txt`.

## Запуск и остановка

- `Запустить демо.cmd` / `Start-Demo.ps1`: проверенная по SHA256 загрузка официального cloudflared при необходимости, затем скрытый фоновый запуск.
- `data/demo/links.txt`: актуальная ссылка на сайт и `/admin/`.
- `data/demo/running.json`: PID и состояние Telegram, без секретов.
- `Остановить демо.cmd` / `Stop-Demo.ps1`: завершить туннель, очередь, приложение и закрыть базу. Дождитесь исчезновения `running.json` перед новым запуском.
- `data/demo/stdout.log`, `stderr.log`: диагностика без токена и тел сообщений. В консоли настройки токен скрыт.

Приложение слушает только `127.0.0.1:4185`; промежуточный прокси — `127.0.0.1:4190`. Локальная версия на 4180 может продолжать работать с собственной базой. Прокси проверяет домен и HTTPS, заменяет подставленные X-Forwarded-* на Cloudflare client IP. Первичное создание владельца через публичный API выключено; защищённые cookie и проверка Origin работают с текущим HTTPS-адресом. Для поисковых роботов задан `noindex` (это не контроль доступа).

Любой получатель ссылки может открыть сайт и отправить тестовую заявку. Кабинет и CRM требуют входа. Не вводите реальные данные гостей в этот демонстрационный запуск. Туннель не имеет гарантированного uptime; доступность нужно проверить на сети тестировщика.

## Проверка

`pnpm check`, `pnpm test` проверяют общий код, идемпотентность, Telegram с подменённой доставкой, авторизацию, CRM, TLS и правила прокси. Реальный браузер и живой Telegram проверяются отдельно; прохождение локальных тестов не доказывает доставку настоящему боту.
