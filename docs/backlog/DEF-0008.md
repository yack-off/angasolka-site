## Описание

При обрыве: «Failed to fetch» в расчёте, отправке и статусе. При таймауте quote/status: «signal timed out». Таймаут orders обрабатывается понятным русским сообщением.

## Воспроизведение

- Среда: Windows, Codex In-app Browser (Chromium), рабочий public/; сервер 127.0.0.1:4183, изолированная PGlite memory.
- Предусловия: тестовый каталог и синтетические заявки; рабочие данные не используются.

1. На изолированном стенде оборвать соединение при quote, orders или status.
2. Отдельно задержать quote/status более 15 секунд.
3. Прочитать сообщение и восстановить соединение.

- Ожидаемый результат: Русское понятное сообщение с предложением повторить действие; для orders учтено неопределённое состояние сохранения.
- Фактический результат: При обрыве: «Failed to fetch» в расчёте, отправке и статусе. При таймауте quote/status: «signal timed out». Таймаут orders обрабатывается понятным русским сообщением.
- Доказательства: FE-15; обрыв после сохранения orders также проверен в FE-11. Повторы quote/status и orders после обрыва работали. [Подробный отчёт](../testing/runs/2026-09-28-0857-frontend-regression.md).

## Критерий исправления

Все проверенные сетевые отказы объясняются по-русски; введённые данные сохраняются, повтор не создаёт дубликат.

- Причина: В общих обработчиках выводится error.message; специальная обработка TimeoutError есть только при отправке orders.
- На момент первоначальной диагностики изменения приложения не вносились; пользователь запросил тестирование и регистрацию.
- На момент первоначальной диагностики проверка после исправления не выполнялась.
- Непроверенное: другие браузерные движки.
- На момент первоначальной диагностики дефект не был исправлен.
- Публикация: не выполнялась.

Сетевые отказы для расчёта, отправки и статуса показывают русские сообщения; поля и возможность повтора сохраняются. Обрыв проверен в браузере, ветви таймаута quote/status проверены исполнением исходного JS с TimeoutError.
